# Feature check

Before the schema was written, each feature doc was read against the decisions (D1 to D27), the schema review, and the readiness reviews in PR #5. This page records the result: what each release 1 feature needs from the database, where it lives, and the gaps that are still open. Feature 13 (Physical shop) is release 2 and was checked only to make sure nothing here blocks it.

## Open gaps

None of these blocks the schema. Each is either a question for Asif or a small doc fix.

| #   | Gap                                                                                                                   | What the schema does now                                                                                  | Needs                               |
| --- | --------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| 1   | Feature 03 promises a merge that can be undone for 7 days; the schema review cut `contact_merges`.                    | Merges are final and recorded in `audit_log` with the moved ids.                                          | Asif: keep undo or drop the promise |
| 2   | Feature 03's import offers "create a second record" for a phone that already exists, but a phone is unique per store. | The unique index stays; import offers "update existing" or "skip".                                        | Doc fix in feature 03               |
| 3   | D16 says risky admin actions need two people, but no list says which actions.                                         | `staff_approvals` takes any action name and payload.                                                      | A list in feature 12                |
| 4   | Feature 12's engineering section mentions an "admin database role"; ADR 0005 uses the app role plus support grants.   | No admin role exists.                                                                                     | Doc fix in feature 12               |
| 5   | The upazila list and Bangla names need an official source (BBS).                                                      | 8 divisions and 64 districts seeded; upazilas come with DB-6.                                             | Task DB-6                           |
| 6   | Notification escalation (who gets a push when nobody answers, and when) is not fully specified (F08-11).              | `notifications.dedupe_key` per user, `push_subscriptions` ready.                                          | Rules in feature 10                 |
| 7   | Abuse reports for the admin trust and safety queue have no table.                                                     | None. An `abuse_reports` table is additive when the screen is designed.                                   | Admin design                        |
| 8   | Admin announcements (banner to all shops) have no table.                                                              | Stored as a `platform_settings` key.                                                                      | None unless they grow               |
| 9   | Analytics metric definitions (F08-10).                                                                                | `store_daily_metrics` is one long table keyed by metric name, so the list can change without a migration. | Task ANA-1                          |

D27 closed the last identity question (saving the buyer's own phone); see [isolation-and-access.md](isolation-and-access.md#customer-identity-d26-d27).

Questions that do not change the schema: Q1 (prices and limits are rows in `plans`), Q2 (WhatsApp BSP), Q7 (Inquiry stays a chat flag), Q8 (models are settings), Q11 (an organisation table is additive), Q13 (`external_ref` columns are ready), Q15 (semaphore lives in Valkey).
